# Таро Онлайн — первая рабочая версия

Русскоязычный многостраничный статический сайт. Без зависимостей npm, платных API, базы данных и обязательного сервера.

## Запуск и сборка

Нужен Node.js 22 или новее.

```sh
npm test
npm run build
```

Готовые файлы находятся в `dist`. Их нужно отдавать HTTP-сервером; открытие index.html двойным щелчком не поддерживается из-за абсолютных маршрутов и модулей. Во время разработки после пересборки перезапустите статический сервер, если он удерживает старый каталог dist.

## Публикация на Render

Создать НОВЫЙ независимый репозиторий `3779008-boop/tarot-online` (название проверить на доступность). Не использовать репозитории бота и других проектов.
Создать Static Site: build command `node build.mjs`, publish directory `dist`, auto-deploy выключен. Серверный тариф не требуется. Бесплатный уровень Render имеет общие лимиты трафика и сборок: не включать платные опции без разрешения владельца.

Перед публичной индексацией задать:

- `SITE_URL`: точный HTTPS-адрес опубликованного сайта без конечного слеша. Если переменная отсутствует, используется предоставляемый Render `RENDER_EXTERNAL_URL`. В локальном режиме без обоих адресов включается noindex, robots запрещает обход, sitemap пустой — это преднамеренно.
- `CONTACT_EMAIL`: публичная почта для обращений. Нельзя автоматически публиковать почту из профиля GitHub без согласия.
- `METRIKA_ID`: номер счётчика, необязателен. Без него аналитика полностью отключена. При наличии счётчик включается только после согласия посетителя.
- `WEBMASTER_TOKEN`: код верификации Яндекс Вебмастера, необязателен.

Затем дополнить политику конфиденциальности реквизитами владельца и фактическими условиями хостинга. После публикации проверить главную, вложенные страницы и HTTP-статус неизвестного адреса. Не создавать SPA rewrite `/* → /index.html`: это многостраничный сайт, неизвестный адрес должен возвращать 404.

## Где менять содержание

- `cards.txt`: 78 строк, разделитель `|`; поля: название, slug, тема, прямое значение, перевёрнутое, отношения, работа, совет, условная оценка Да/Нет (-1/0/1). Не использовать `|` внутри текста.
- `spreads.json`: позиции, контексты, расположение и пояснения 13 сценариев (карта дня + 12 раскладов).
- `articles.json`: 5 руководств; разделы задаются парами «заголовок, текст».
- `engine.mjs`: случайность, перемешивание и синтез.
- `app.mjs`: выбор карт, локальное сохранение, поиск, фильтры и согласие на аналитику.
- `style.css`: стили и адаптивность.
- `build.mjs`: генерация HTML, SVG-карт и SEO-файлов.

## Реклама

РСЯ НЕ подключена и сайт НЕ проходил модерацию. В раскладах предусмотрен скрытый контейнер `.ad-slot[data-ad-slot="after-reading"]`, расположенный после интерактивной зоны. Пока он пуст, он не занимает место.

После одобрения подключать только официальный неизменённый код Яндекса. Не загружать рекламный код через стороннюю баннерную систему, не менять содержимое объявлений. При авторасстановке сначала выяснить поддерживаемый способ исключения интерактивной зоны — не считать произвольный CSS-класс инструкцией РСЯ. Если исключение не поддерживается, выбрать ручные блоки вне интерактива. Не подключать одновременно ручные и автоматические блоки без проверки дублей. Обновить политику и механизм согласия по фактической конфигурации. Запрос поддержке находится в docs/research.md.

## Аналитика

Подготовлены события `spread_start` и `spread_complete` с идентификатором расклада. Просмотры, источники и повторные визиты — стандартные отчёты подключённой Метрики. Сам счётчик и цели ещё не созданы. Доход — из отчётов РСЯ, не из локального состояния сайта. Вебвизор и clickmap отключены. Личные вопросы не вводятся, карта не передаётся в событии.

## Резервирование

Исходники хранить в отдельном GitHub-репозитории; создавать коммит перед обновлением. `dist` воспроизводится сборкой. Архив релиза включает исходники, готовую сборку и отчёты. Секреты и платёжные данные не нужны. Не коммитить `.env`.

## Известные ограничения версии

- Публикация и модерация ещё не выполнены; для создания репозитория в доступном браузере нужен вход GitHub.
- Контакт редакции и реквизиты владельца не заданы; страницы контактов и политики пока предварительные.
- У каждой карты есть один учебный пример сочетания с соседней картой; это не полный справочник всех 3003 пар.
- Общие трактовки основаны на правилах, а не свободном ИИ-анализе вопроса. Разные позиции и значения учитываются, но синтез намеренно ограничен.
- Иллюстрации оригинальные геометрические, не сюжетная колода Уэйта.
- Перевёрнутые положения выбираются с вероятностью 1/2. Карта дня закрепляется только для браузера и устройства, зависит от местной даты; очистка хранения позволяет выбрать снова.
- Точные частоты и сезонность Вордстата не получены; SEO-гипотезы нельзя считать замеренным спросом.
- Нужна окончательная редактура текстов и проверка опубликованной версии до заявки в РСЯ.
